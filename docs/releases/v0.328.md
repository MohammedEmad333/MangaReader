### What's new
- Missing or moved covers are recorded in memory immediately, so the library refresh sweep can see them without waiting for disk.
- Cover-repair markers are persisted in bounded background batches: after 32 changes or a short 350 ms batch window.
- Large library scrolls no longer enqueue one full SharedPreferences rewrite for every failed cover.
- Duplicate suppression, the 2,000-entry safety cap and removal after a successful cover repair are preserved.

### Validation
- JVM tests cover deduplication, capacity, clearing and snapshot isolation.
- The Android emulator workflow validates the merged reader build and instrumentation suite.
